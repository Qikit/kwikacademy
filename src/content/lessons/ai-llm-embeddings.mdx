## Зачем это

До сих пор мы разбирали одну модель — ту, что предсказывает следующий токен. Но чтобы строить полезные системы, нужен второй инструмент: способ измерить, **насколько два текста близки по смыслу**. Не по общим словам, а именно по значению.

Зачем это на практике: поиск по документации, который находит нужную статью, даже если пользователь спросил другими словами; дедупликация похожих тикетов; рекомендации «похожего»; и главное — фундамент RAG (подключения знаний к модели), которым мы займёмся через два урока. Всё это стоит на эмбеддингах.

Разобравшись с эмбеддингами и векторным пространством смыслов, ты научишься прикидывать, где семантический поиск обыграет поиск по ключевым словам, — и почему эмбеддер это вообще не генеративная модель.

## Ядро: смысл превращается в точку в пространстве

<Callout type="purple" title="Суть">
**Эмбеддинг** — это представление текста числовым вектором (списком из сотен или тысяч чисел) так, что тексты, близкие по смыслу, оказываются близкими точками в пространстве, а далёкие по смыслу — далёкими. Отдельная модель-**эмбеддер** переводит каждый кусок текста в такую точку. После этого «насколько похоже по смыслу» превращается в «насколько близко в пространстве» — а это уже обычная геометрия, которую легко считать.
</Callout>

Вся хитрость вот в чём: смысл — вещь расплывчатая, а расстояние между точками — точная и вычислимая. Эмбеддер берёт на себя перевод из первого во второе. «Машина не заводится» и «авто сломалось» не делят ни одного слова, но по смыслу почти одно и то же — и хороший эмбеддер поставит их рядом.

<Reveal q="Может ли семантический поиск найти документ, в котором нет ни одного слова из запроса?">
Да — в этом вся его суть. Поиск идёт не по совпадению слов, а по близости смысла. Запрос «как убрать утечку памяти» найдёт статью «устранение memory leak в сервисе», хотя общих слов там нет. Обычный поиск по ключевым словам такой документ бы пропустил.
</Reveal>

## Как устроено: вектор, пространство, близость

Разберём по частям, без математики.

- **Вектор.** Эмбеддер выдаёт на текст список чисел фиксированной длины — например, 1024 числа. Каждое число — координата вдоль одной из осей «пространства смыслов». Сам по себе один вектор ничего не значит; смысл появляется в сравнении с другими.
- **Пространство смыслов.** Представь очень многомерное пространство, где обучение расставило тексты так, что близкое по значению лежит рядом. `кот` рядом с `кошка`, но далеко от `трактор`. Осей не три, а сотни — но принцип «рядом = похоже» тот же.
- **Близость.** Похожесть меряют **косинусной близостью** — по сути, углом между двумя векторами: чем меньше угол, тем ближе смысл. Число обычно в диапазоне от −1 до 1, где ближе к 1 — почти одно и то же, около 0 — не связаны.

Важно: эмбеддер — **не та же модель**, что генерирует текст. Это отдельный тип модели, обученный не продолжать текст, а раскладывать его по пространству смыслов. Одна отвечает на вопросы, другая мерит близость — и путать их не стоит.

<Callout type="blue" title="Своей embeddings-модели у Anthropic нет — и это нормально">
Anthropic не выпускает собственный эмбеддер: в документации они прямо направляют к сторонним провайдерам (например, Voyage AI). Свои эмбеддеры есть у OpenAI, Google, Cohere и других — это отдельный рынок моделей. Практический вывод: эмбеддер под задачу ты выбираешь **отдельно** от того, какой LLM отвечает пользователю. И ещё одно следствие — векторы от разных эмбеддеров живут в **разных** пространствах и **несравнимы** между собой: нельзя проэмбеддить корпус одной моделью, а запрос — другой.
</Callout>

## Как на практике: семантический поиск

Схема, на которой держится половина прикладных LLM-систем:

1. **Заранее** прогоняешь весь свой корпус (документы, статьи, тикеты) через эмбеддер и складываешь получившиеся векторы в **векторную базу**. Это делается один раз (и обновляется при изменении корпуса).
2. **На запрос** эмбеддишь вопрос пользователя тем же эмбеддером и ищешь в базе **ближайшие** векторы — топ-k самых близких документов.
3. Дальше эти документы либо показываешь пользователю (поиск), либо передаёшь в LLM как контекст (RAG — следующие уроки).

Вот весь путь целиком — текст превращается в вектор через эмбеддер провайдера, и дальше считается близость двух векторов (Python, актуально на 2026-07 — проверь у себя; у Anthropic своего эмбеддера нет, берём стороннего — здесь Voyage AI):

```python
import numpy as np
import voyageai  # эмбеддер стороннего провайдера — Anthropic направляет именно к нему

vo = voyageai.Client()  # ключ берётся из окружения

def embed(text):
    # текст → вектор; имя актуальной модели сверь в доке провайдера
    return vo.embed([text], model="voyage-3").embeddings[0]

def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))

vec_query = embed("машина не заводится")
vec_doc = embed("двигатель заглох на морозе")
print(cosine(vec_query, vec_doc))  # ближе к 1 — ближе по смыслу
```

Сам вызов эмбеддера — это API конкретного провайдера (у OpenAI, Google, Cohere он свой), но метрика близости у всех одна и та же геометрия. В реальной системе перебор всех векторов вручную заменяет векторная БД — она хранит эмбеддинги и быстро находит ближайшие.

## Три разбора

**Разбор 1. Синонимы без общих слов.**
Пользователь пишет в поддержку: «авто не реагирует на ключ». В базе есть статья «двигатель не запускается: диагностика стартера». Общих слов — ноль. Поиск по ключевым словам вернёт пусто. Семантический — поставит эту статью в топ, потому что векторы близки. Вывод: там, где люди описывают одно и то же разными словами (а это почти всегда), близость по смыслу бьёт совпадение слов.

**Разбор 2. Контекст разводит одинаковые слова.**
Слово «замок» само по себе двусмысленно — здание или запор. Но эмбеддер работает не с голым словом, а с фразой. «Средневековый замок на холме» и «замок заклинило в двери» дадут **далёкие** векторы, потому что контекст фразы разный. Отсюда практика: эмбеддь осмысленные куски (предложение, абзац), а не отдельные слова — контекст и есть то, что даёт смысл.

**Разбор 3. Размер куска решает.**
Ты эмбеддишь базу знаний. Если резать на слишком большие куски (целые главы), один вектор смешивает много тем и близость размывается — запрос про одну деталь плохо находит нужное место. Если резать слишком мелко (по одному предложению), теряется контекст, и куски становятся неразличимы. Практичный ориентир — куски по смысловому блоку (абзац-раздел). Точный размер подбирают под корпус, но крайности вредят одинаково.

## Ключевой поиск или семантический

<Compare leftLabel="Поиск по ключевым словам" rightLabel="Семантический поиск">
  <div slot="left">
  • Ищет точное совпадение слов<br/>
  • Промахивается на синонимах и перефразах<br/>
  • Не нужен эмбеддер и векторная БД<br/>
  • Хорош для точных терминов, кодов, ID<br/>
  • «Утечка памяти» ≠ «memory leak»
  </div>
  <div slot="right">
  • Ищет по близости смысла<br/>
  • Находит синонимы и перефразы<br/>
  • Нужен эмбеддер + векторная база<br/>
  • Хорош для вопросов на естественном языке<br/>
  • «Утечка памяти» ≈ «memory leak»
  </div>
</Compare>

На практике их часто **сочетают** (гибридный поиск): ключевой ловит точные термины и коды, семантический — смысл. Но понимать разницу нужно, чтобы не удивляться, почему одно находит, а другое нет.

## Типовые ошибки

| Ошибка | Почему вредит | Что вместо |
| --- | --- | --- |
| Путать эмбеддер и генеративную LLM | Это разные модели с разной задачей | Эмбеддер мерит близость, LLM генерирует текст |
| Сравнивать векторы от разных эмбеддеров | Разные пространства — числа несравнимы | Один эмбеддер на весь корпус и запросы |
| Ждать от близости точных фактов | Близко по смыслу ≠ верно по факту | Близость — для поиска, факты проверять отдельно |
| Эмбеддить слишком крупные куски | Один вектор смешивает темы, близость плывёт | Резать по смысловому блоку |
| Эмбеддить отдельные слова без контекста | Теряется контекст, смысл неоднозначен | Эмбеддить фразы и абзацы |
| Считать семантику заменой ключевого поиска | Точные термины и коды семантика ловит хуже | Гибрид: ключевой + семантический |

## Шпаргалка

| Что | Коротко |
| --- | --- |
| Эмбеддинг | Текст → вектор чисел, близкое по смыслу — рядом |
| Эмбеддер | Отдельная модель (не генеративная LLM) |
| Близость | Косинусная, ближе к 1 — ближе смысл |
| Anthropic | Своего эмбеддера нет — берут стороннего (Voyage и др.) |
| Разные эмбеддеры | Разные пространства — векторы несравнимы |
| Семантический поиск | Эмбеддишь корпус → ищешь ближайшие к запросу |
| Кусок для эмбеддинга | Смысловой блок, не глава и не слово |
| Ключевой vs семантика | Термины/коды vs смысл; на практике — гибрид |
