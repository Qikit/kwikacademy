## Зачем это

В прошлом уроке ты провёл цикл вызова целиком: объявил модели `get_weather`, получил `tool_use`, выполнил функцию и вернул `tool_result`. Теперь ассистенту нужны календарь, трекер задач, веб-поиск и база заказов. Каждую интеграцию ты пишешь сам: схема, вызов чужого API, ошибки, авторизация. Потом те же интеграции просит соседняя команда, и их пишут второй раз.

Три приложения и четыре сервиса дают двенадцать интеграций, если каждую писать под каждое приложение. **MCP** (Model Context Protocol) меняет счёт: сервис один раз оборачивают в сервер, и его подключает любое приложение, которое понимает протокол. Вокруг MCP два заблуждения: будто это новый способ вызывать инструменты взамен цикла из прошлого урока и будто готовый сервер похож на библиотеку, которую поставил и забыл. С первым ты ждёшь от модели не того, со вторым пускаешь в систему чужой код с твоими правами.

После урока ты сможешь решить, писать инструмент самому или подключить готовый, и подключить MCP-сервер: вызвать его своим клиентом и выбрать, как он попадёт к модели.

## Ядро: протокол общий, цикл вызова прежний

<Callout type="purple" title="Суть">
**MCP** — открытый протокол, по которому ИИ-приложение подключается к внешним системам. **Сервер** отдаёт инструменты, приложение получает их список и вызывает нужный. Модель в обмене по протоколу не участвует: она по-прежнему видит описания инструментов и просит вызов. Меняется то, **кто написал инструмент и где он выполняется**: в твоём коде, на платформе вендора (компании, чью модель ты вызываешь) или в MCP-сервере.
</Callout>

У каждого нового инструмента теперь три возможных источника. Авторы протокола сравнивают MCP с USB-C: разъём один, устройства разные. Но флешка не диктует компьютеру, что делать, а текст чужого сервера модель читает как часть задачи.

Прежде чем раскрыть ответ, ответь сам, хотя бы про себя.

<Reveal q="В документации сервиса написано: «у нас есть MCP-сервер». Значит ли это, что его инструменты заработают только с Claude?">
Нет. Сервер разговаривает с приложением, а какая модель стоит за приложением, протоколу безразлично. На сайте MCP среди приложений с его поддержкой названы Claude, ChatGPT, Visual Studio Code и Cursor (на 2026-10). Правило: сервер привязан к протоколу, к модели привязано только приложение.
</Reveal>

## Как устроено: хост, клиент, сервер

**Хост** (host) — ИИ-приложение, которое разговаривает с моделью: Claude Desktop, редактор кода с ассистентом, твой бэкенд с чат-ботом. **Клиент** (client) — часть хоста, которая держит соединение ровно с одним сервером: на три сервера три клиента. **Сервер** (server) — программа, которая отдаёт хосту данные и действия. Сервер файловой системы запускается на той же машине, сервер Sentry работает у Sentry и отвечает по сети. А сервер, где работает сама модель, к MCP-серверам не относится.

Сервер отдаёт три вида возможностей:

| Возможность | Кто решает, когда брать | Что это |
| --- | --- | --- |
| **Инструменты** (tools) | Модель | Функции с действием: найти рейсы, создать событие |
| **Ресурсы** (resources) | Хост | Данные только для чтения с адресом: схема базы, файл |
| **Промпты** (prompts) | Пользователь | Шаблоны запросов, которые вызывают явно, например слэш-командой |

Сообщения идут в формате JSON-RPC: хост шлёт `tools/list` и получает описания, потом `tools/call` с именем и аргументами. Доставляет их **транспорт**: **stdio** (стандартные ввод и вывод процесса) для локального сервера, который клиент сам запускает, или **Streamable HTTP** для удалённого. На 2026-10 действует версия протокола 2026-07-28.

Нет. Сама модель может попросить только инструмент. Ресурсом распоряжается хост: он решает, положить ли схему в контекст. Правило: инструменты выбирает модель, ресурсы — хост, промпты — пользователь.
</Reveal>

## Как устроено: кто выполняет инструмент

Инструменты различаются тем, где выполняется код. **Клиентский инструмент** (client tool) выполняется в твоём приложении: модель возвращает `tool_use`, ты запускаешь код и отправляешь `tool_result`. Таким был `get_weather` из прошлого урока. **Серверный инструмент** (server tool) выполняется на платформе вендора: ты включаешь его в запросе, а в ответе приходит готовый результат. У Anthropic (на 2026-10) это веб-поиск со ссылками на источники, по 10 долларов за 1000 поисков плюс токены, и исполнение кода в песочнице без интернета. Их хватает, когда задача типовая и не требует доступа к твоим системам. С MCP-сервером серверный инструмент роднит только слово: MCP-сервер может работать и на твоём ноутбуке.

**MCP connector** переносит на платформу и подключение сервера: ты передаёшь в Messages API адрес удалённого MCP-сервера, и клиентом работает она сама. Ограничений два (бета, на 2026-10): из всего протокола поддерживаются только инструменты, а сервер должен быть доступен публично по HTTPS.

И connector, и свой клиент приводят в систему чужой код и чужой текст. Локальный сервер работает на твоей машине с правами того, кто его запустил. Тому, что сервер пишет о своих инструментах, спецификация велит не доверять, пока он не проверен. А результаты вызовов — сторонний текст, и в нём могут оказаться инструкции, адресованные модели. Защиту разбирает урок про безопасность.

<Reveal q="Как думаешь, сколько описаний инструментов уйдёт модели, если к ассистенту подключено пять серверов по двадцать инструментов, а пользователь спросил, сколько будет 17 × 23?">
Все сто, если ты ничего не настраивал. Описания подключённых инструментов входят в каждый запрос как входные токены. По документации Anthropic набор из пяти серверов (GitHub, Slack, Sentry, Grafana, Splunk) может занять около 55 тысяч токенов, а точность выбора падает, когда инструментов больше 30–50.
</Reveal>

Против такого счёта у вендора есть **поиск инструментов** (tool search). Ты добавляешь в `tools` сам инструмент поиска, а остальным ставишь `defer_loading: true`, это отложенная загрузка. Их описания не попадают в контекст, пока модель не найдёт нужные по каталогу: спросили про погоду — подгрузился `get_weather`.

Так же, по требованию, подгружают инструкции: это **Agent Skills**. Инструмент — функция с аргументами и результатом, а skill — папка с инструкцией `SKILL.md`, скриптами и шаблонами, например правила оформления отчётов компании с шаблоном документа. В контексте постоянно лежат только имя и описание skill, около 100 токенов; инструкцию модель читает, когда задача подошла. В API skill работает только вместе с инструментом исполнения кода.

## Свой сервер и клиент

Поставь пакет командой `pip install mcp` (Python 3.10+, пакет `mcp` 2.2.0, запущено 2026-10-02 — проверь у себя). Сервер с одним инструментом сохрани как `weather_server.py`:

```python
from mcp.server import MCPServer

mcp = MCPServer("weather")

WEATHER = {
    "Париж": "+18°C, ясно",
    "Берлин": "+12°C, дождь",
}


@mcp.tool()
def get_weather(city: str) -> str:
    """Текущая погода в городе.
    Вызывай, когда спрашивают про погоду сейчас.
    Возвращает температуру и осадки одной строкой.
    Прогноз на другие дни не даёт."""
    return WEATHER.get(city, "нет данных")


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

Схему аргументов писать не пришлось: `MCPServer` собирает её из подсказок типов, а описание берёт из строки документации функции. Клиент запускает сервер как процесс, спрашивает список инструментов и вызывает один. Сохрани его как `client.py` рядом с сервером и запусти из этой папки командой `python client.py`:

```python
import asyncio
import sys

from mcp import Client, StdioServerParameters

server = StdioServerParameters(
    command=sys.executable,
    args=["weather_server.py"],
)


async def main():
    async with Client(server) as client:
        print("протокол:", client.protocol_version)
        listing = await client.list_tools()
        for tool in listing.tools:
            print(tool.name)
            print(tool.description)
            schema = tool.input_schema
            print(schema["properties"], schema["required"])
        result = await client.call_tool(
            "get_weather", {"city": "Париж"}
        )
        print(result.content[0].text)


asyncio.run(main())
```

Вывод:

```text
протокол: 2026-07-28
get_weather
Текущая погода в городе.
Вызывай, когда спрашивают про погоду сейчас.
Возвращает температуру и осадки одной строкой.
Прогноз на другие дни не даёт.
{'city': {'title': 'City', 'type': 'string'}} ['city']
+18°C, ясно
```

Первая строка — версия протокола, на которой сошлись клиент и сервер. Дальше то, что раньше ты писал руками: имя, описание, схема аргументов.

<Reveal q="Как думаешь, что произойдёт, если запустить python weather_server.py в терминале без клиента?">
Сервер ничего не напечатает и будет ждать. Он читает сообщения JSON-RPC из стандартного ввода, по одному в строке, и отвечает строкой в стандартный вывод. Подашь на вход строку с `tools/call`, где в `_meta` указаны версия протокола и возможности клиента, — получишь строку с результатом; без `_meta` придёт ошибка. Поэтому в stdio-сервере нет `print()`: по спецификации в stdout идут только сообщения протокола, логи пишут в поток ошибок stderr.
</Reveal>

## Как подключить сервер к модели

Локальный сервер ты подключаешь своим кодом. Хост в этом примере — сам скрипт: он берёт у сервера список инструментов, кладёт его в `tools` и крутит знакомый цикл, только вместо своей функции зовёт `call_tool`. Клиент MCP асинхронный, поэтому и модель вызываем через `AsyncAnthropic` (Python, Anthropic SDK 1.11, сверено с документацией 2026-10-02 — проверь у себя):

```python
import asyncio
import sys

from anthropic import AsyncAnthropic
from mcp import Client, StdioServerParameters

llm = AsyncAnthropic()
server = StdioServerParameters(
    command=sys.executable,
    args=["weather_server.py"],
)


async def ask(tools, messages):
    return await llm.messages.create(
        model="claude-opus-5-5",
        max_tokens=1024,
        tools=tools,
        messages=messages,
    )


async def run_tool(client, call):
    out = await client.call_tool(call.name, call.input)
    texts = [
        c.text for c in out.content if c.type == "text"
    ]
    return {
        "type": "tool_result",
        "tool_use_id": call.id,
        "content": "\n".join(texts),
        "is_error": out.is_error,
    }


async def chat(client, tools, question):
    messages = [{"role": "user", "content": question}]
    resp = await ask(tools, messages)
    while resp.stop_reason == "tool_use":
        results = []
        for block in resp.content:
            if block.type != "tool_use":
                continue
            results.append(await run_tool(client, block))
        messages += [
            {"role": "assistant", "content": resp.content},
            {"role": "user", "content": results},
        ]
        resp = await ask(tools, messages)
    return resp


async def main():
    async with Client(server) as client:
        listing = await client.list_tools()
        tools = [
            {
                "name": t.name,
                "description": t.description,
                "input_schema": t.input_schema,
            }
            for t in listing.tools
        ]
        question = "Какая погода в Париже?"
        resp = await chat(client, tools, question)
        for block in resp.content:
            if block.type == "text":
                print(block.text)


asyncio.run(main())
```

Модели уходят те же три поля, что и у самописного инструмента: `name`, `description`, `input_schema`. Если инструмент упал, сервер возвращает результат с флагом ошибки, и код передаёт его модели через `is_error`.

Удалённый сервер может подключить сама платформа. Наш сервер переходит на сеть заменой одного аргумента, `mcp.run(transport="streamable-http")`, после чего его выставляют по HTTPS. Дальше работает MCP connector. В `mcp_toolset` здесь выключено всё, кроме одного инструмента (Python, Anthropic SDK 1.11, сверено с документацией 2026-10-02 — проверь у себя):

```python
from anthropic import Anthropic

llm = Anthropic()
question = "Какая погода в Париже?"

resp = llm.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{
        "type": "url",
        "url": "https://mcp.example.com/mcp",
        "name": "weather",
    }],
    tools=[{
        "type": "mcp_toolset",
        "mcp_server_name": "weather",
        "default_config": {"enabled": False},
        "configs": {"get_weather": {"enabled": True}},
    }],
    messages=[{"role": "user", "content": question}],
)
for block in resp.content:
    if block.type == "mcp_tool_use":
        print("вызов:", block.name, block.input)
    elif block.type == "mcp_tool_result":
        print("ошибка:", block.is_error)
    elif block.type == "text":
        print(block.text)
```

Цикл здесь крутит платформа: она сама запрашивает список инструментов, вызывает нужный и кладёт в ответ блоки `mcp_tool_use` и `mcp_tool_result`. Серверу с авторизацией добавляют поле `authorization_token`; получать и обновлять токен доступа (OAuth) должен ты сам.

## Как на практике

- **Сначала поищи готовое.** Веб-поиск и исполнение кода есть у вендора, у многих сервисов есть свои MCP-серверы. Своё пиши для своей логики и своих систем.
- **Подключай инструменты, а не сервер целиком.** В `mcp_toolset` ставь `enabled: False` в `default_config` и включай нужное в `configs`. В своём хосте фильтруй список перед отправкой в `tools`.
- **Перед действием, которое что-то меняет, спрашивай человека.** Спецификация советует всегда оставлять ему возможность отклонить вызов. Connector вызывает инструмент сам, внутри запроса, поэтому документация советует выключать в нём такие инструменты, если нужен шаг подтверждения.
- **Считай описания входными токенами.** От 10 инструментов или больше 10 тысяч токенов описаний Anthropic советует включать поиск инструментов.
- **Локальному серверу давай минимум прав.** Прочитай команду запуска, прежде чем добавлять сервер в приложение: он работает с правами клиента. Чужой сервер запускай в песочнице.

## Три разбора

**Разбор 1. Свой веб-поиск.**
Команда пишет инструмент `search_web`: ходит в поисковик и чистит HTML. Через месяц половина задач в трекере касается этого инструмента: поменялась вёрстка выдачи, пользователи просят ссылки на источники. Ход: готовый веб-поиск вендора, который выполняется на платформе и возвращает ответ со ссылками. Вывод: типовую задачу, которой не нужен доступ к твоим системам, бери готовым серверным инструментом.

**Разбор 2. Сервер календаря целиком.**
Ассистенту нужно искать встречи, и разработчик подключает MCP-сервер календаря без настроек. Вместе с `search_events` модель получает `delete_all_events` и `share_calendar_publicly`. Ход: в `mcp_toolset` выключить всё по умолчанию и включить один `search_events`. Вывод: готовый сервер подключают списком разрешённых инструментов.

**Разбор 3. Где MCP лишний.**
У тебя один скрипт поддержки и один инструмент `get_order_status`, который читает твою базу. Оформить его MCP-сервером — значит завести отдельный процесс и транспорт, а подключать этот сервер больше некому. Ход: обычный инструмент в коде приложения. Вывод: протокол окупается, когда инструмент нужен нескольким приложениям или его пишет другая команда. Это рабочее правило, в документации его нет.

## Типовые ошибки

| Ошибка | Почему вредит | Что вместо |
| --- | --- | --- |
| Подключать сервер целиком | Лишние описания в контексте, опасные действия доступны модели | Список разрешённых инструментов |
| Считать MCP-сервер обычной библиотекой | Локальный сервер получает права клиента, его тексты идут в контекст | Проверить источник, дать минимум прав |
| Ждать, что connector увидит локальный сервер | Он подключается только к публичным HTTPS-серверам | Свой клиент по stdio или сервер за HTTPS |
| Печатать через `print()` в stdio-сервере | В stdout разрешены только сообщения протокола | Логи в stderr через `logging` |
| Копировать код из старых статей | В `mcp` 2.x нет `FastMCP`, в протоколе нет `initialize` | Сверить версию пакета и спецификации |

Возьми инструмент из своей задачи, например поиск по списку задач.

1. Напиши сервер с одним инструментом: функция с подсказками типов и строкой документации «что делает и когда вызывать». Сохрани файл рядом с `client.py`.
2. В клиенте поменяй имя файла сервера и вызов. Запусти и проверь, что твой инструмент есть в списке.
3. Вызови инструмент без обязательного аргумента и напечатай `result.is_error`.
4. Реши, как сервер попадёт к модели — своим клиентом или через connector — и нужен ли этому инструменту сервер.

<div slot="solution">
Рабочий вариант для поиска задач:

```python
from mcp.server import MCPServer

mcp = MCPServer("tasks")

TASKS = [
    "Обновить прайс до пятницы",
    "Позвонить поставщику",
    "Сверить прайс с сайтом",
]


@mcp.tool()
def find_task(query: str) -> str:
    """Ищет задачи по слову в названии.
    Вызывай, когда просят найти или показать задачу.
    Возвращает названия, по одному в строке.
    Ничего не меняет."""
    q = query.lower()
    found = [t for t in TASKS if q in t.lower()]
    return "\n".join(found) or "ничего не найдено"


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

Клиент из урока с вызовом `find_task` и аргументом `{"query": "прайс"}` напечатал:

```text
протокол: 2026-07-28
find_task
Ищет задачи по слову в названии.
Вызывай, когда просят найти или показать задачу.
Возвращает названия, по одному в строке.
Ничего не меняет.
{'query': {'title': 'Query', 'type': 'string'}} ['query']
Обновить прайс до пятницы
Сверить прайс с сайтом
```

Вызов без `query` не уронил клиент: пришёл результат, где `is_error` равен `True`, а текст начинается с «Error executing tool find_task: 1 validation error». Так об ошибке узнаёт модель и может исправить аргументы. К модели этот сервер проще подключить своим клиентом: он локальный, а connector видит только публичные серверы. Отдельный сервер оправдан, если поиск задач нужен нескольким приложениям.

## Шпаргалка

| Что | Коротко |
| --- | --- |
| Что отдаёт сервер | Инструменты (модель), ресурсы (хост), промпты (пользователь) |
| Клиентский инструмент | Выполняется твоим кодом, нужен `tool_result` |
| Серверный инструмент | Выполняется у вендора: веб-поиск, исполнение кода |
| MCP connector | `mcp_servers` и `mcp_toolset`; только инструменты, только публичный HTTPS |
| Много инструментов | От 10 штук или 10 тысяч токенов — `defer_loading` и поиск |
| Agent Skills | Папка с инструкцией; в контексте постоянно только имя и описание |
| Чужой сервер | Описания и результаты недоверенные, прав — минимум |
