## Зачем это

В прошлом уроке `if` и `when` стали выражениями: `if (a > b) a else b` сразу даёт значение. Такую строку скоро захочется назвать и вызывать из разных мест. Тут и просыпаются привычки из Java. Ты переносишь сервис уведомлений, а в исходнике класс `NotificationUtils` с приватным конструктором и три **перегрузки** (overloads) `send`: методы с одним именем и разными параметрами. Рядом вызов `export(report, true, false)`, и чтобы понять, какой флаг что включает, приходится открывать объявление.

Если перенести это на Kotlin один в один, всё скомпилируется. Но каждый новый необязательный параметр потянет ещё одну перегрузку, а перепутанные местами `true` и `false` компилятор пропустит молча: типы совпадают. В Kotlin эти задачи решают значения по умолчанию, именованные аргументы и функции прямо в файле, без класса вокруг. В Java их нет, поэтому руки по привычке пишут перегрузки и `static`.

После урока ты сможешь объявить функцию с блочным телом или телом-выражением, заменить набор перегрузок одной функцией со значениями по умолчанию и вызвать её так, чтобы вызов читался без заглядывания в объявление.

## Ядро: одна функция с умолчаниями вместо перегрузок

<Callout type="purple" title="Суть">
Функцию объявляют словом `fun`, у каждого параметра обязателен тип, а тип результата пишут после скобок через двоеточие. **Значение по умолчанию** (дальше — просто умолчание) делает параметр необязательным, поэтому одна функция закрывает все случаи, под которые в Java заводили перегрузки ради необязательных параметров. **Именованный аргумент** (`urgent = true`) показывает прямо в вызове, какое значение куда идёт. Класс для функции не нужен: её объявляют **на верхнем уровне** файла.
</Callout>

Официальные соглашения о коде Kotlin советуют то же самое: умолчания вместо перегрузок и имена для аргументов типа `Boolean`.

Прежде чем раскрыть ответ, ответь сам, хотя бы про себя.

<Reveal q="В Java у метода connect три перегрузки: (host), (host, port) и (host, port, timeout). Их заменили одной функцией с умолчаниями. Какой вызов станет возможен, хотя в Java его не сделать?">
Таймаут без порта: `connect(host, timeoutMs = 1_000)`. В Java такую перегрузку не объявить: сигнатура `connect(String, int)` уже занята версией с портом, и javac ответит «method connect(String,int) is already defined». Пришлось бы передавать порт явно или придумывать методу новое имя.
</Reveal>

## Как устроено: объявление, тело и Unit

**Параметр** (parameter) — имя с типом в объявлении функции, например `port: Int`. **Аргумент** (argument) — значение, которое передают при вызове. Тип параметра, в отличие от типа переменной, компилятор не выводит, его пишут всегда. **Тип результата** (return type) стоит после скобок через двоеточие.

<KotlinPlayground>

```kotlin
fun max(a: Int, b: Int) = if (a > b) a else b

fun area(width: Int, height: Int): Int {
    val result = width * height
    return result
}

fun printTitle(title: String) {
    println("== $title ==")
}

fun main() {
    printTitle("Функции")
    println(max(3, 7))
    println(area(4, 5))
}
```

</KotlinPlayground>

Запусти: программа напечатает заголовок, 7 и 20. Потом удали `: Int` у `area` и запусти снова. Компилятор (Kotlin 2.4.20) ответит «Return type mismatch: expected 'Unit', actual 'Int'».

У `area` **блочное тело** (block body): инструкции в фигурных скобках, значение возвращают через `return`. Если функция возвращает что-то кроме `Unit`, тип результата у такого тела обязателен. По документации, Kotlin его не выводит, потому что в запутанном блоке тип стал бы неясен читателю, а иногда и компилятору. Без типа функция с блочным телом возвращает `Unit`, поэтому `return result` и не компилируется.

У `max` **тело-выражение** (expression body): одно выражение после знака `=`, без скобок и `return`. Тип результата здесь компилятор выводит сам. Это та же строка `if (a > b) a else b` из прошлого урока, только с именем. Так же в функцию превращается `when`:

```kotlin
fun grade(score: Int) = when (score) {
    in 90..100 -> "отлично"
    in 70..89 -> "хорошо"
    else -> "повтори тему"
}
```

А `printTitle` ничего не возвращает. Тип результата у неё всё равно есть: **`Unit`**, тип с единственным значением, которое тоже называется `Unit`. По справочнику Kotlin, он соответствует `void` из Java. Указывать `: Unit` в объявлении не нужно.

Теперь предскажи, что напечатает эта программа:

```kotlin
fun total(price: Int, qty: Int) {
    price * qty
}

fun main() {
    println(total(3, 4))
}
```

<Reveal q="Что напечатает println(total(3, 4))?">
Напечатает `kotlin.Unit`, и компилятор не возразит. Типа результата у `total` нет, как у `printTitle`, поэтому `price * qty` вычисляется и отбрасывается, а `println` получает единственное значение `Unit`. Чтобы вернуть результат из блока, нужны тип и `return`, а для одного выражения проще тело-выражение `= price * qty`.
</Reveal>

Ещё одна разница с Java касается самих параметров. В Java параметр метода можно переприсвоить, если он не объявлен `final`. В Kotlin **параметры функции** только для чтения, как `val`, и строка `price = price * 90 / 100` внутри функции не скомпилируется с ошибкой «'val' cannot be reassigned». Для нового значения заводят локальную `val result = …`.

## Как устроено: умолчания, имена и vararg

**Значение по умолчанию** (default value) пишут после типа параметра: `port: Int = 80`. Если аргумент не передан, подставляется умолчание, иначе оно даже не вычисляется.

<Callout type="blue" title="Если знаешь Java — лесенка перегрузок здесь не нужна">
В Java необязательный параметр делают перегрузкой, где короткий метод вызывает длинный и подставляет недостающее. Отсюда лесенки из трёх-четырёх `send` и новый метод на каждый новый параметр. В Kotlin ту же работу делает одна функция, у которой `subject` по умолчанию равен `"Без темы"`, а `urgent` — `false`. Перегрузки с разными типами параметров, вроде `show(x: Int)` и `show(x: String)`, в Kotlin остаются. Умолчания заменяют только лесенку необязательных.
</Callout>

Вторая половина приёма — **именованный аргумент** (named argument): при вызове перед значением ставят имя параметра, `timeoutMs = 1_000`. Такие аргументы можно перечислять в любом порядке. Обычные аргументы без имени называют **позиционными** (positional): их сопоставляют с параметрами по порядку. Если пропускаешь аргумент в середине, все следующие пиши по имени.

<KotlinPlayground>

```kotlin
fun connect(
    host: String,
    port: Int = 80,
    timeoutMs: Int = 5_000,
) = "$host:$port, таймаут $timeoutMs мс"

fun main() {
    println(connect("example.com"))
    println(connect("example.com", 8080))
    println(connect("example.com", timeoutMs = 1_000))
}
```

</KotlinPlayground>

Запусти, потом добавь вызов `connect(timeoutMs = 500, host = "localhost")`: аргументы идут в другом порядке, а строка выходит правильной. Затем замени третий вызов на `connect("example.com", 1_000)`. Программа напечатает «example.com:1000, таймаут 5000 мс»: число без имени ушло в `port`, а ошибки нет, ведь оба параметра `Int`.

Именовать аргументы можно только у Kotlin-функций. На вызов `Math.max(a = 1, b = 2)` компилятор выдаст несколько ошибок, среди них «Named arguments are prohibited for non-Kotlin functions». Документация объясняет это тем, что байт-код Java не всегда хранит имена параметров.

<Reveal q="Объявили fun greet(greeting: String = «Привет», name: String) и вызвали greet(«Аня»). Это скомпилируется?">
Нет: «No value passed for parameter 'name'». Позиционный аргумент «Аня» занимает первый параметр, `greeting`, и для `name` ничего не остаётся. Умолчанием параметра, который стоит перед обязательным, можно воспользоваться только через имя: `greet(name = "Аня")`. Поэтому необязательные параметры удобнее ставить в конец списка.
</Reveal>

Если число аргументов заранее неизвестно, параметр помечают **`vararg`** (variable number of arguments). В него можно передать сколько угодно значений, в том числе ни одного. Внутри функции он виден как массив. Такой параметр в функции может быть только один, и обычно он последний. Вариант с `vararg` есть и у `maxOf` из стандартной библиотеки: `maxOf(4, 9, 2, 8)` вернёт 9.

<KotlinPlayground>

```kotlin
fun total(vararg prices: Int): Int {
    var sum = 0
    for (price in prices) sum += price
    return sum
}

fun main() {
    println(total())
    println(total(100, 250))
    val cart = intArrayOf(300, 450)
    println(total(*cart, 50))
}
```

</KotlinPlayground>

`intArrayOf` создаёт массив `IntArray`, на JVM это `int[]` из Java; подробно о массивах — в уроке про коллекции. Готовый массив передают через **оператор распаковки** (spread operator), звёздочку перед именем: `total(*cart, 50)`. Убери `*` и запусти: «Argument type mismatch: actual type is 'IntArray', but 'Int' was expected». В Java массив можно передать в `int...` как есть, а в Kotlin — только через `*`.

## Как устроено: где живут функции

Все функции в примерах выше объявлены прямо в файле, вне класса. Это **функции верхнего уровня** (top-level functions). В Java для той же задачи заводят утилитный класс вроде `java.util.Collections`, который по документации «состоит исключительно из статических методов». В Kotlin функцию кладут в файл, названный по смыслу, например `Slugs.kt`. Имён вроде `Utils` соглашения советуют избегать.

<Reveal q="Функцию slugify положили на верхний уровень файла Slugs.kt. В каком классе её будет искать Java-код?">
В классе `SlugsKt`. Компилятор превращает функции верхнего уровня в статические методы класса с именем файла и суффиксом `Kt`, поэтому из Java вызов выглядит как `SlugsKt.slugify(title)`.
</Reveal>

<Callout type="blue" title="Как функции верхнего уровня видны из Java">
Так же `Prices.kt` даёт класс `PricesKt`, а `Main.kt` — `MainKt`. Имя класса меняют аннотацией `@file:JvmName("Prices")` в начале файла. Аннотация `@JvmOverloads` добавляет для Java перегрузки, по одной на каждый параметр со значением по умолчанию. Подробно — в уроке про Gradle и Java-экосистему.
</Callout>

Бывает, что помощник нужен только одной функции. Тогда его объявляют прямо в ней. Такая **локальная функция** (local function) видна только там и видит локальные переменные внешней функции:

```kotlin
fun printReceipt(bread: Int, milk: Int) {
    var total = 0
    fun add(name: String, price: Int) {
        total += price
        println("$name: $price ₽")
    }
    add("Хлеб", bread)
    add("Молоко", milk)
    println("Итого: $total ₽")
}
```

Вызов `printReceipt(60, 90)` напечатает три строки, последняя «Итого: 150 ₽».

## Как на практике

- **Начинай с одной функции.** Если параметр может отсутствовать, дай ему умолчание вместо новой перегрузки.
- **Называй флаги и однотипные аргументы.** `export(report, notify = true)` читается без объявления перед глазами, а два `Boolean` с именами не перепутать.
- **Одно выражение пиши через `=`.** `fun area(w: Int, h: Int): Int = w * h` короче блока с `return`.
- **Пиши тип результата у функций, которые вызывают из других файлов и модулей.** Так советуют тур по Kotlin и соглашения для библиотек: тип виден сразу и не поменяется случайно вместе с реализацией.
- **Клади функции в файл по смыслу**, например `Prices.kt`, и не заворачивай их в класс.

<Callout type="teal" title="Как принято">
Имена функций по соглашениям Kotlin — camelCase с маленькой буквы, обычно глагол или глагольная фраза: `close`, `readPersons`. Длинную сигнатуру переносят по параметру на строку с отступом в четыре пробела, как у `connect` выше. Запятую после последнего параметра (trailing comma) соглашения поощряют в объявлениях. Вокруг `=` в именованном аргументе ставят пробелы: `notify = true`.
</Callout>

## Три разбора

**Разбор 1. Лесенка перегрузок из Java.**
Сервис уведомлений перенесли с Java как есть: три функции `send`, и короткие вызывают длинную, подставляя «Без темы» и `false`. Для срочного письма без темы придётся повторять «Без темы» в каждом вызове или заводить четвёртую перегрузку. Ход: одна `send` с `subject: String = "Без темы"` и `urgent: Boolean = false`. Старые вызовы не меняются, новый выглядит как `send(to, urgent = true)`. Вывод: необязательному параметру в Kotlin хватает умолчания, отдельная функция под него не нужна.

**Разбор 2. `true, false` в вызове.**
На ревью строка `export("q3", true, false)`, у функции параметры `compress` и `notify`, оба `Boolean` с умолчанием `false`. Автор хотел уведомить, а включил сжатие: перепутал порядок, и компилятор этого не заметил. Ход: `export("q3", notify = true)`, а `compress` можно не писать. Вывод: когда параметры одного типа, от перестановки защищает только имя, поэтому соглашения и советуют имена для `Boolean`.

**Разбор 3. Где умолчания не срабатывают.**
Kotlin-файл `Prices.kt` с функцией `formatPrice(amount: Int, currency: String = "₽")` подключили к старому Java-коду. Java-разработчик пишет `PricesKt.formatPrice(1500)` и получает ошибку компиляции.

<Reveal q="Почему Java не видит вызов formatPrice с одним аргументом и как это исправить?">
Java видит только полную сигнатуру `formatPrice(int, String)`, об умолчаниях Kotlin её компилятор ничего не знает. Исправление — пометить функцию `@JvmOverloads`: тогда для Java появится ещё и `formatPrice(int)`.
</Reveal>

Вывод: значения по умолчанию работают в Kotlin-коде, а на границе с Java их превращают в перегрузки аннотацией.

## Типовые ошибки

| Ошибка | Почему вредит | Что вместо |
| --- | --- | --- |
| Перегрузки ради необязательных параметров | Каждый новый параметр — ещё метод, редкие сочетания недоступны | Значения по умолчанию |
| `export(r, true, false)` без имён | Перестановку однотипных аргументов компилятор не заметит | `export(r, notify = true)` |
| Блочное тело без типа результата | Функция вернёт `Unit`: `return x` не скомпилируется, а без `return` значение потеряется | `: Int` или тело через `=` |
| Передать массив в `vararg` как есть | «Argument type mismatch» | `total(*cart)` |
| Параметр с умолчанием перед обязательным | Умолчание доступно только через имя | Необязательные параметры — в конец |

## Практикум

<Practice title="Сверни перегрузки в одну функцию" checklist={["Осталась одна функция greet", "У greeting и loud есть значения по умолчанию", "Третий вызов — greet(«Вика», loud = true), без лишнего «Привет»", "Тип String указан, если тело блочное", "Первые два вызова не изменились", "Программа печатает «Привет, Аня!», «Здравствуй, Борис!» и «ПРИВЕТ, ВИКА!»"]}>
Ниже перегрузки, перенесённые с Java как есть. Замени три функции `greet` одной со значениями по умолчанию. Первые два вызова в `main` не трогай. Третий перепиши так, чтобы в нём остались только имя и флаг: «Привет» и так совпадает с умолчанием. Вывод программы не должен измениться.

<KotlinPlayground>

```kotlin
fun greet(name: String): String =
    greet(name, "Привет")

fun greet(name: String, greeting: String): String =
    greet(name, greeting, false)

fun greet(
    name: String,
    greeting: String,
    loud: Boolean,
): String {
    val text = "$greeting, $name!"
    return if (loud) text.uppercase() else text
}

fun main() {
    println(greet("Аня"))
    println(greet("Борис", "Здравствуй"))
    println(greet("Вика", "Привет", true))
}
```

</KotlinPlayground>

<div slot="solution">
Рабочий вариант:

```kotlin
fun greet(
    name: String,
    greeting: String = "Привет",
    loud: Boolean = false,
): String {
    val text = "$greeting, $name!"
    return if (loud) text.uppercase() else text
}

fun main() {
    println(greet("Аня"))
    println(greet("Борис", "Здравствуй"))
    println(greet("Вика", loud = true))
}
```

Первые два вызова работают без изменений, недостающие аргументы берутся из умолчаний. В третьем `greeting` пропущен, поэтому `loud` передан по имени. Позиционный `greet("Вика", true)` не скомпилируется: `true` попадёт в параметр `greeting` типа `String`. Тип `String` нужен, потому что тело блочное.
</div>
</Practice>

## Шпаргалка

| Что | Коротко |
| --- | --- |
| Объявление | `fun area(w: Int, h: Int): Int { return w * h }` |
| Тело-выражение | `fun area(w: Int, h: Int) = w * h`, тип выводится |
| Ничего не возвращает | Тип `Unit`, `: Unit` не пишут |
| Блочное тело без типа | Возвращает `Unit` |
| Параметры | Только для чтения, как `val` |
| Значение по умолчанию | `port: Int = 80` |
| Именованный аргумент | `connect(host, timeoutMs = 1_000)` |
| Пропустил аргумент | Все следующие — по имени |
| `vararg` | `fun total(vararg p: Int)`, массив — `total(*cart)` |
| Вызов из Java | `PricesKt.formatPrice(…)`, перегрузки — `@JvmOverloads` |
