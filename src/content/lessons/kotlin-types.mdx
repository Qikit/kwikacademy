## Зачем это

В прошлом уроке ты запустил первую программу, разобрался с `val` и `var` и видел строку `"Изучаю $language, урок $lessons"`, а подробности о строках мы отложили до этого урока. Теперь представь, что ты переводишь на Kotlin кусок Java-сервиса и по привычке пишешь `val status = count > 0 ? "есть" : "нет"`. Компилятор Kotlin 2.4.20 отвечает ошибкой «Syntax error: Unexpected tokens (use ';' to separate expressions on the same line).» Тернарного оператора в Kotlin нет.

Замена находится за минуту, потому что `if` в Kotlin сам возвращает значение. Хуже привычки, на которые компилятор не жалуется. `break` в ветке `when` ведёт себя не так, как в `switch`. Если ты пришёл из JavaScript, где `7 / 2` равно 3,5, удивит целочисленное деление. А строка `"Итого: $price.toInt()"` при `price = 9.99` напечатает совсем не цену. Кое-где Kotlin, наоборот, страхует лучше Java: `==` сравнивает строки по содержимому, а `Int` не превращается в `Long` без спроса.

После урока ты сможешь писать `if` и `when` как выражения, собирать строки шаблонами, проходить диапазоны в цикле и объяснить, где числа и строки в Kotlin ведут себя не так, как ждёт Java-разработчик.

## Ядро: if и when возвращают значение

<Callout type="purple" title="Суть">
В Kotlin `if` и `when` — **выражения** (expressions): у них есть значение, его можно присвоить переменной или сразу напечатать. Поэтому тернарный оператор не нужен, его работу делает `if (a > b) a else b`. Вместо `switch` пишут `when`, и его ветки не проваливаются одна в другую.
</Callout>

На практике меняется форма кода. В Java объявляют переменную, а потом присваивают ей значение в ветках. В Kotlin переменная сразу получает значение всего `if` или `when` и остаётся `val`. Чем это надёжнее, мы выяснили в прошлом уроке.

Прежде чем открыть разбор, ответь сам, хотя бы про себя.

<Reveal q="Коллега сжал var label = «файлов»; if (count == 1) label = «файл» в одну строку: val label = if (count == 1) «файл». Скомпилируется ли это?">
Нет. Компилятор ответит «'if' must have both main and 'else' branches when used as an expression»: значение нужно при любом условии, поэтому у `if`-выражения ветка `else` обязательна. Рабочий вариант — `val label = if (count == 1) "файл" else "файлов"`. Правило: если значение `if` куда-то идёт, пиши обе ветки.
</Reveal>

## Как устроено: числа, символы и строки

**Базовые типы** (basic types) на каждый день: `Int` и `Long` для целых чисел, `Double` для дробных, `Boolean`, `Char` для одного символа и `String` для текста. В коде они выглядят как классы, у числа можно вызвать функцию: `5.toLong()`. Примитивов вроде `int` в синтаксисе нет, но на JVM компилятор хранит числа, символы и логические значения как примитивы, где может.

`Int` вмещает числа до 2 147 483 647, `Long` занимает 64 бита. Тип подсказывает **литерал** (literal), то есть значение, записанное прямо в коде: у `5L` тип `Long`, у `2.5` — `Double`, у `2.5f` — `Float`. Если тип не указан, целое без суффикса становится `Int`, а если не помещается, то `Long`: `3_000_000_000` уже `Long`. С указанным типом литерал подстраивается под него, поэтому `val big: Long = 5` из прошлого урока компилируется.

<details>
<summary>Byte, Short и другие записи чисел</summary>

`Byte` и `Short` берут, когда их требует API или формат данных. Подчёркивания в `1_000_000` нужны только для читаемости, `0xFF` и `0b1010` записывают `Int` в шестнадцатеричном и двоичном виде.

</details>

Не запускай программу ниже, пока не ответишь на вопрос под ней.

<KotlinPlayground>

```kotlin
fun main() {
    val total = 7
    val people = 2
    println(total / people)
    println(total % people)
    println(total / 2.0)
    val max = Int.MAX_VALUE
    println(max + 1)
}
```

</KotlinPlayground>

<Reveal q="Сначала предскажи: что напечатают четыре println?">
`3`, `1`, `3.5` и `-2147483648`. В первой строке **целочисленное деление**: у двух `Int` результат тоже `Int`, дробная часть отбрасывается, а `%` во второй строке возвращает остаток. Хватит одного `Double`, и деление станет дробным. `Int.MAX_VALUE + 1` не помещается в 32 бита, происходит **переполнение** (overflow): значение перескакивает на минимальное, и ни компилятор, ни программа об этом не сообщают.
</Reveal>

Запусти и сверься. Потом замени `max + 1` на `max + 1L`: результат станет `Long`, и программа напечатает `2147483648`.

<Callout type="blue" title="Если знаешь Java — Int не станет Long сам">
С числами Java-привычки почти работают: деление и переполнение устроены так же. Не работает одна, неявное расширение. В Java `long total = count;` компилируется, потому что `int` расширяется до `long` сам. В Kotlin на `val total: Long = count` компилятор ответит «Initializer type mismatch: expected 'Long', actual 'Int'», и нужно **явное преобразование** (explicit conversion) `count.toLong()`. Kotlin запрещает неявные переходы между числовыми типами все сразу, даже безопасный из `Int` в `Long`, потому что часть таких переходов теряет данные: в Java `float f = 123456789;` молча превратит число в 123456792. В арифметике типы смешивать можно, `count + 1L` даёт `Long`.
</Callout>

А вот с `Char`, одним символом в одинарных кавычках, Java-привычка подведёт. В Java `char` — целый тип, и `'a' + 1` там равно 98. В Kotlin `Char` не число: из `'a' + 1` получится символ `'b'`, а код символа берут явно, `'a'.code`.

**Строки.** `String` неизменяема: `uppercase()`, `replace()` и другие функции возвращают новую строку. Собирать строку удобнее всего **строковым шаблоном** (string template). `$name` подставляет значение переменной, `${items * 250}` — результат выражения. Знак `$` захватывает только имя, поэтому в `"Итого: $price.toInt()"` подставится `price`, а `.toInt()` напечатается как текст. Вызов берут в фигурные скобки: `"Итого: ${price.toInt()}"` при `price = 9.99` даст «Итого: 9», потому что `toInt()` отбрасывает дробную часть. Кириллица тоже годится в имя переменной, так что `"$itemsшт."` компилятор прочитает как переменную `itemsшт` и ответит «Unresolved reference 'itemsшт'». Скобки нужны и здесь: `"${items}шт."`.

**Многострочная строка** (multiline string) в тройных кавычках хранит переводы строк и отступы как есть, а escape-последовательности вроде `\n` в ней не работают. Отступ из кода в значении обычно не нужен, его убирает `trimIndent()` вместе с пустыми первой и последней строками.

```kotlin
val text = """
    Привет, $name!
    Заказ готов.
""".trimIndent()
```

В `text` окажутся две строки без отступов. `trimIndent()` срезает только общий отступ, вложенные строки сохраняют свой. Если текст начинается сразу после `"""`, общего отступа нет и срезать нечего; тогда строки начинают с `|` и вызывают `trimMargin()`. В текстовых блоках Java отступ убирается сам, в Kotlin — только вызовом функции.

Сравнивают строки через `==`. Это **структурное равенство** (structural equality): Kotlin вызывает `equals` и смотрит на содержимое. `===` — **равенство ссылок** (referential equality): оно истинно, только если обе переменные указывают на один и тот же объект.

<KotlinPlayground>

```kotlin
fun main() {
    val a = "Kotlin"
    val prefix = "Kot"
    val b = prefix + "lin"
    println(a == b)
    println(a === b)
    val items = 3
    println("Товаров: $items, итого ${items * 250} ₽")
}
```

</KotlinPlayground>

<Reveal q="Предскажи, что напечатают a == b и a === b, и только потом запускай.">
`true` и `false`. Текст одинаковый, поэтому `==` возвращает `true`. Но `b` собрана во время работы программы и лежит в памяти отдельным объектом, и `===` это замечает. Две одинаковые строки-литерала JVM хранит одним объектом, и для них `===` вернул бы `true`. Полагаться на это нельзя: строки сравнивай через `==`.
</Reveal>

После запуска замени `${items * 250}` на `$items * 250` и посмотри, что изменится в последней строке.

<Callout type="blue" title="Если знаешь Java — == сравнивает строки по содержимому">
В Java `a == b` для строк сравнивает ссылки. По спецификации Java, для разных объектов результат ложный, даже если символы совпадают, поэтому пишут `a.equals(b)`. В Kotlin `==` сам вызывает `equals`, и `a.equals(b)` писать незачем. Роль `==` из Java здесь играет `===`: он проверяет, один ли это объект.
</Callout>

## Как устроено: if, when и циклы по диапазонам

Ветка `if` может быть блоком в фигурных скобках. Тогда значение ветки — последнее выражение в блоке:

```kotlin
val fee = if (amount > 1000) {
    println("Крупный платёж")
    0
} else {
    50
}
```

При `amount = 1500` программа напечатает «Крупный платёж», а `fee` получит 0.

**`when`** заменяет `switch` и длинные цепочки `if-else`. С аргументом он сравнивает его со значениями веток по порядку и выполняет первую подходящую. В одной ветке можно перечислить несколько значений через запятую или проверить **диапазон** (range) через `in`:

<KotlinPlayground>

```kotlin
fun main() {
    val code = 404
    val text = when (code) {
        200 -> "OK"
        301, 302 -> "Редирект"
        in 400..499 -> "Ошибка клиента"
        in 500..599 -> "Ошибка сервера"
        else -> "Неизвестный код"
    }
    println("$code: $text")
}
```

</KotlinPlayground>

Запусти, потом поставь `code = 302`, а затем `700`. После этого удали ветку `else`, и компилятор ответит «'when' expression must be exhaustive. Add an 'else' branch.». Если значение `when` используется, он должен покрыть все случаи, а все числа ветками не перечислишь. **Инструкция** (statement) — это `when`, чьё значение нигде не используется. С числом или строкой в аргументе она обходится без `else`: не совпало ничего — ничего и не выполнится. А если аргумент `Boolean`, компилятор с Kotlin 1.7 и в инструкции требует ветки для `true` и `false` или `else`; подробно о таких типах — в уроке про моделирование данных.

Без аргумента `when` проверяет условия по очереди, как цепочка `if-else if`:

```kotlin
val advice = when {
    temp < 0 -> "Пуховик"
    temp < 15 -> "Куртка"
    else -> "Футболка"
}
```

При `temp = 18` получится «Футболка»: первые два условия ложны. При `temp = -5` выйдет «Пуховик», а если поменять местами две первые ветки, то «Куртка»: `-5 < 15` тоже истинно, и до `temp < 0` дело не дойдёт. Срабатывает первая истинная ветка, поэтому порядок важен.

**Проваливания** (fall-through), как в классическом `switch`, у `when` нет. По спецификации Kotlin, после первой подходящей ветки остальные условия даже не проверяются, поэтому `break` в конце ветки не нужен. В Java с версии 14 так же работает `switch` со стрелками `case L ->` (JEP 361), а старый `case L:` без `break` по-прежнему проваливается в следующий.

Диапазон `1..10` включает обе границы, **полуоткрытый диапазон** (open-ended range) `1..<10` заканчивается на 9. Шаг задают через `step`, счёт вниз — через `downTo`. В `if` и `when` слова `in` и `!in` проверяют вхождение, в том числе в диапазон символов: `'k' in 'a'..'z'` истинно. В `for` слово `in` означает обход, и `!in` там не бывает.

<KotlinPlayground>

```kotlin
fun main() {
    for (i in 0..<5 step 2) print(i)
    println()
    for (i in 5..1) print(i)
    println()
    for (i in 5 downTo 1) print(i)
}
```

</KotlinPlayground>

<Reveal q="Предскажи, что напечатают три цикла, и только потом запускай.">
`024`, пустая строка и `54321`. `0..<5` не включает 5, а `step 2` берёт каждое второе число. `5..1` пуст: `..` считает только вверх, и цикл не выполнится ни разу, без ошибки и предупреждения. Для счёта вниз нужен `downTo`.
</Reveal>

После запуска замени `step 2` на `step 3` и посмотри на первую строку.

`for` по диапазону короче, чем `for (int i = 0; i < n; i++)` в Java, а `while` и `do-while` такие же, как в Java: `do-while` проверяет условие после тела, поэтому тело выполнится хотя бы раз. `break` и `continue` тоже работают как в Java.

```kotlin
fun main() {
    for (i in 1..5) {
        when (i) {
            3 -> {
                println("три")
                break
            }
            else -> println(i)
        }
    }
    println("конец")
}
```

<Reveal q="Что напечатает эта программа?">
1, 2, «три» и «конец». `break` внутри `when` относится к ближайшему циклу, поэтому программа выходит из `for`, и 4 и 5 не печатаются. В Java такой же `break` в `switch` завершил бы только `switch`.
</Reveal>

## Как на практике

- **Присваивай результат `if` и `when`.** `val price = when (zone) { … }` вместо `var price` и присваиваний в ветках. Переменная остаётся `val`, а компилятор проверит, что значение есть при любом условии.
- **Смотри на типы, когда делишь.** Два `Int` дают `Int`. Для дробного результата сделай `Double` хотя бы один операнд: `total.toDouble() / count`.
- **Переводи в `Long` до умножения.** `days * 24L * 60 * 60 * 1000` считает в `Long` с первого шага. `toLong()` в конце опоздает, переполнение уже случилось.
- **Сравнивай строки через `==`.** `===` проверяет, один ли это объект, и для одинакового текста может дать и `true`, и `false`.
- **Не пиши `break` в ветках `when`.** Ветки не проваливаются, а внутри цикла `break` завершит весь цикл.

<Callout type="teal" title="Как принято">
Соглашения о коде Kotlin советуют `if` для двух вариантов и `when` для трёх и больше. Полуоткрытый диапазон пишут через `..<`: `for (i in 0..<n)` вместо `0..n - 1`. В коде, написанном до появления `..<`, встретишь `0 until n`. Эта запись не устарела и значит то же самое, но в JetBrains заметили, что с `until` легко решить, будто верхняя граница включена.
</Callout>

## Три разбора

**Разбор 1. Миллисекунды за месяц.**
Разработчик считает таймаут в миллисекундах и пишет `val ms: Long = days * 24 * 60 * 60 * 1000` при `days = 30`. Kotlin строку не компилирует, потому что справа `Int`, а слева `Long`. Первое, что приходит в голову, — обернуть всё в `(…).toLong()`. Код компилируется и печатает `-1702967296`: 2 592 000 000 не помещается в `Int`, и переполнение случилось до преобразования. Правильный ход — сделать `Long` первый множитель, `days * 24L * 60 * 60 * 1000`, тогда получится `2592000000`. В Java строка `long ms = days * 24 * 60 * 60 * 1000;` компилируется сразу и тихо даёт то же отрицательное число, Kotlin хотя бы заставляет остановиться. Вывод: тип меняют до вычисления, `toLong()` в конце не спасает.

**Разбор 2. switch с проваливанием.**
В Java-коде выходные дни объединены через пустой `case`, а у пятницы свой тип:

```java
switch (day) {
    case "SAT":
    case "SUN":
        type = "выходной";
        break;
    case "FRI":
        type = "короткий";
        break;
    default:
        type = "будний";
}
```

При переводе легко перенести и пустой `case`, и `break`. В Kotlin пустых веток нет, а несколько значений перечисляют через запятую:

```kotlin
val type = when (day) {
    "SAT", "SUN" -> "выходной"
    "FRI" -> "короткий"
    else -> "будний"
}
```

`when` сравнивает `day` со значением ветки через `==`, то есть по содержимому строки. Вывод: проваливание, которое в Java объединяло case, в Kotlin становится списком через запятую, а `break` исчезает.

**Разбор 3. Где `when` лишний.**
В коде встречается такое:

```kotlin
val label = when (isAdmin) {
    true -> "Админ"
    false -> "Пользователь"
}
```

Это работает, и `else` не нужен, потому что у `Boolean` два значения и ветки покрывают оба. Но две ветки проще читаются как `if` в одну строку: `val label = if (isAdmin) "Админ" else "Пользователь"`. Обратный случай — цепочка `if … else if … else if` из четырёх веток, её удобнее переписать в `when` без аргумента. Вывод: `when` окупается, когда вариантов три и больше, а на двух он только добавляет строк.

## Java и Kotlin

| Было в Java | В Kotlin | Что важно |
| --- | --- | --- |
| `c ? a : b` | `if (c) a else b` | `if` — выражение |
| `switch` с `break` | `when` | ветки не проваливаются |
| `s.equals(t)` | `s == t` | сравнивает содержимое |

## Типовые ошибки

| Ошибка | Почему вредит | Что вместо |
| --- | --- | --- |
| `(a * b).toLong()` для больших чисел | Переполнение уже случилось в `Int` | `a.toLong() * b` или `L` у литерала |
| `total / count` для среднего | Дробная часть отбрасывается | `total.toDouble() / count` |
| `===` для сравнения строк | Одинаковый текст в разных объектах даёт `false` | `==` |
| `break` в ветке `when` внутри цикла | Завершает весь цикл | Убрать: ветки не проваливаются |
| `"$price.toInt()"` | Подставится только `price`, остальное станет текстом | `"${price.toInt()}"` |
| `for (i in 10..1)` | Диапазон пуст, цикл не выполнится | `10 downTo 1` |
| `if` без `else` справа от `=` | Ошибка компиляции | Добавить `else` |

## Практикум

<Practice title="Переведи расчёт доставки с Java на Kotlin" checklist={["price получает значение из when, без var и break", "B и C стоят в одной ветке через запятую", "size получает значение из if вместо тернарного оператора", "Цена за килограмм считается в Double: 62.5 вместо 62", "Строка собрана шаблоном, без +", "Программа печатает «Доставка: 500 ₽, крупная, 62.5 ₽/кг»"]}>
Вот фрагмент на Java. В нём есть ошибка: цена за килограмм считается неверно.

```java
int weight = 8;
String zone = "B";
int price;
switch (zone) {
    case "A": price = 300; break;
    case "B":
    case "C": price = 500; break;
    default: price = 900;
}
String size = weight > 5 ? "крупная" : "обычная";
double perKg = price / weight;
System.out.println("Доставка: " + price + " ₽, "
    + size + ", " + perKg + " ₽/кг");
```

Перепиши его на Kotlin без `var` и без `+`, исправь ошибку и запусти. Программа должна напечатать «Доставка: 500 ₽, крупная, 62.5 ₽/кг».

<KotlinPlayground>

```kotlin
fun main() {
    val weight = 8
    val zone = "B"
    // переведи остальное сюда
}
```

</KotlinPlayground>

<div slot="solution">
Рабочий вариант:

```kotlin
fun main() {
    val weight = 8
    val zone = "B"
    val price = when (zone) {
        "A" -> 300
        "B", "C" -> 500
        else -> 900
    }
    val size = if (weight > 5) "крупная" else "обычная"
    val perKg = price.toDouble() / weight
    println("Доставка: $price ₽, $size, $perKg ₽/кг")
}
```

«B» и «C» стоят в одной ветке через запятую, `break` не нужен. Ошибка исходника в `price / weight`: в Java деление двух `int` дало 62, и только потом число стало `double` 62.0. В Kotlin строка `val perKg: Double = price / weight` даже не скомпилируется: «Initializer type mismatch: expected 'Double', actual 'Int'». А `price.toDouble() / weight` считает в `Double` и даёт 62.5.
</div>
</Practice>

## Шпаргалка

| Что | Коротко |
| --- | --- |
| Вместо `c ? a : b` | `val x = if (c) a else b` |
| Выбор из нескольких | `when (x)`, ветки `1, 2 ->`, `in 3..9 ->`, `else ->` |
| `if` и `when` как выражения | У `if` всегда нужен `else`, у `when` — если ветки покрывают не все значения |
| Целочисленное деление | `7 / 2` — 3, `7 / 2.0` — 3.5 |
| `Int` в `Long` | `x.toLong()`; в арифметике `x + 1L` |
| Переполнение | `Int.MAX_VALUE + 1` даёт `-2147483648` без ошибки |
| Шаблон | `"$name"`, `"${a + b}"` |
| Многострочная строка | `"""…""".trimIndent()` |
| Сравнение строк | `==` — содержимое, `===` — один объект |
| Диапазоны | `1..10`, `1..<10`, `10 downTo 1`, `step 2` |
